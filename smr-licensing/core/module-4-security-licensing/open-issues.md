# Open Issues

The security cluster: four entries, and the module where the most useful habit is asking whether a given problem is the regulator's to fix at all. Two of these are industry guidance items, one is a threat-basis calibration only the Commission can make, and one is not a regulatory problem in any sense — it is a statute.

**[LI-01 — Counter-UAS defeat authority](../../register/LI-01-counter-uas-defeat-authority.md)** — authority the Commission cannot grant because Congress has not conferred it. The cleanest example on the register of a question that looks regulatory and is not.

**[LI-02 — Campus-scaled critical digital asset identification](../../register/LI-02-campus-scaled-cda-identification.md)** — which shared assets are critical when criticality scales with module count.

**[LI-03 — Shared digital instrumentation and control guidance](../../register/LI-03-shared-digital-ic-guidance.md)** — how you implement controls on a shared architecture once you know which assets matter.

**[LI-04 — State-actor pre-positioning in the threat basis](../../register/LI-04-state-actor-pre-positioning.md)** — the construct was drawn around a different adversary, and only the Commission can redraw it.
