# Open Issues

This module has no register entries of its own, which is the right result: orientation is where the framework is at its most settled. What it does instead is tell you how the register is distributed, so you can read ahead to whichever part of the framework you came for.

Module 1 carries one entry, on pathway selection. Module 2 carries three, all of them versions of the same question — what happens to a safety demonstration when a dozen reactors share the equipment it depends on. Module 3 carries two, on the planning-zone calculation. Module 4 carries four, the security cluster, and it is the module where the distinction between a regulatory problem and a statutory one matters most. Module 5 carries five and is the densest part of the register. Module 6 carries one, on what may be said in public.

One thing to take forward from this module in particular: the design family you chose is not neutral with respect to the register. [LI-05](../../register/LI-05-reduced-epz-conditionality.md) and [LI-07](../../register/LI-07-assc-duration-on-aggregate-demand.md) both resolve differently depending on which barrier set your family credits, because a residual belongs to a barrier set rather than to a reactor in general.
